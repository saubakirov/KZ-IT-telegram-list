## Research Plan

### Gather

- Inventory every public string class emitted from current metadata, North Star, categories, entry records, and generator literals; separate invariant identifiers/proper names from localized meaning and derive finite completeness counts.
- Review every current group, channel, and bot against explicit AI, startups, jobs, events, and engineering inclusion rules; record categories, exceptional handles, exclusions, and ambiguity without keyword inference.
- Recheck the live GitHub/Pages render and official primary specifications only where needed to make route, DOM, metadata, sitemap, Dataset, JSON, and mobile assertions executable.
- Decompose evidence ownership into repository-controlled automated checks, public post-deployment observations, authenticated owner gates, optional-access evidence, and non-guaranteed external outcomes.

### Extract

- Build a constrained configuration space across string ownership/review state, intent-definition representation, render assertion layer, and external evidence disposition without reopening route or site architecture.
- Produce a finite string inventory schema and fail-closed acceptance matrix precise enough for TS acceptance criteria.
- Convert the entry-by-entry audit into exact intent definitions: category selectors, exceptional handles, explicit exclusions, semantics, and stable destinations.
- Define an evidence matrix naming the artifact, environment, assertion, expected value, and failure disposition for GitHub, each Pages route, sitemap, Dataset JSON-LD, and public JSON.

### Challenge

- Stress-test completeness rules against missing/blank/wrong-language values, unchanged proper names, stale generated outputs, and unqualified review claims.
- Prove every included intent member satisfies the declared semantics; attack broad engineering and startup interpretations and ensure every current entry is accounted for as included or excluded.
- Challenge assertions for false positives such as valid-but-wrong HTML, reciprocal-link asymmetry, broken Markdown-special names, duplicate/unstable anchors, and viewport-dependent first-screen claims.
- Confirm authenticated settings and variable retrieval outcomes can be gated without leaving the implementation design unresolved or promising rank/AI inclusion.

## Scope Intent

- **In scope:** finite EN/RU/KK string inventory; qualified-review and fail-closed rules; entry-by-entry five-intent classification; category/handle definitions and exclusions; stable anchors; GitHub/Pages route and DOM assertions; special-character/Telegram-link parity; language/canonical/alternate/sitemap/Dataset/JSON evidence; bounded mobile assertions; public/authenticated/optional/non-guaranteed evidence ownership.
- **Out of scope:** reopening `/`, `/ru/`, `/kk/` or the dedicated static projection; writing/certifying translations; code or generated-output changes; HL/TS/status/journal/iteration-control edits; repository settings changes; broad SEO/AEO research; link-liveness/member-count mutation; a new application or agent-only file.

## Guiding Questions

1. What exact finite inventory and review-state rules make all three language projections complete without translating identifiers or silently falling back?
2. Which exact current handles belong to each of the five intents under narrow explicit semantics, and which tempting candidates must be excluded?
3. What minimum executable evidence set proves the selected GitHub/Pages design while correctly gating authenticated settings and non-guaranteed retrieval outcomes?
